# 疯狂枪王（暂定名）

微信小游戏上的快节奏像素联网射击：2—6 位好友开房，在小地图里空手抢枪、一击必杀，一场打十几局按累计比分排名；击败当前累计比分最高的玩家可额外得分（悬赏领先者）。

玩法类型与比赛结构参考 Duck Game，不复刻其角色、名称、美术或具体武器组合。仓库名 `crazy-gun-king`。

## 项目目标

这是作者的第一款游戏：每周投入五至十小时，本人独立推进，AI 辅助。首要目标是把微信体验版做完、交给朋友试玩，用试玩回答四个问题：

1. 触屏手感是否成立；
2. 联网判定是否公平；
3. 6 人同屏能否看清；
4. 悬赏领先者能否让整场比赛更有悬念。

**首版达到目标的判断**：朋友能在微信体验版中顺利开房，完成多场 2—6 人的完整比赛，上述问题都有试玩观察结果可供下一步决策。能否得到正面结论不作为完成前提；具体观察口径在项目中细化。

首个对外版本只用微信体验版发给朋友试玩，不公开上架。

## 分阶段路线

准备 → 里程碑一：单机手感 → 里程碑二：2 人联网 → 微信体验版。

| 阶段 | 内容 | 完成条件 | 粗估工时（助手估算） |
| --- | --- | --- | --- |
| 准备 | 选定引擎与联网方案，完成引擎入门教程，跑通微信小游戏空项目 | 方案选择及理由写入项目文档；空项目能在微信开发者工具与真机运行 | 15—30 小时（2—6 周） |
| 里程碑一：单机手感 | 一台手机、一人对木桩：1 张地图；移动、跳跃、朝面向射击与少量辅助、拾取与投掷；2 把武器 | 达到手感合格标准（见下） | 30—60 小时（3—12 周） |
| 里程碑二：2 人联网 | 微信分享邀请进房；两台手机同步移动与射击；命中判定、一击必杀、换局与计分 | 两台真机能完成一场多局比赛并正确计分；联网判定的公平感有初步观察 | 50—120 小时（5—24 周） |
| 微信体验版 | 扩到 6 人、3 张地图、约 4 把武器、悬赏、计分板与排名、基本界面、试玩后修改 | 见“项目目标”中的首版判断 | 40—90 小时（4—18 周） |
| **合计** | | | **约 135—300 小时（约 14—60 周）** |

阶段顺序由用户决定；工时是助手粗估，未经数据验证，联网部分不确定性最大，里程碑一完成后用实际用时重新校准。阶段内的逐步安排见 `docs/progress.md`。

## 设计基线（2026-11-14）

以下按决定状态分开记录。助手建议在用户确认前不作为规则；未定事项不在没有试玩或讨论的情况下自行拍板。各条依据见交接文档与想法说明的“关键取舍”。

### 用户已决定

- **平台**：微信小游戏。
- **对手来源**：好友开房为主，随机匹配后置。
- **房间**：每房 2—6 人，满 2 人即可开局；通过微信分享邀请进房，房主开始比赛。
- **AI**：首版不做，好友房不提供 AI。随机匹配阶段再做 AI 补位：凑不齐人时补足空位，使用和真人一样的名字，不表明身份。
- **操作**：朝角色面向射击，可上下调整角度，带少量瞄准辅助；左手移动，右手负责跳跃、射击、拾取与投掷。
- **武器获得**：开局空手，武器出现在地图刷新点，抢到即用。
- **胜负与计分**：一击必杀；以最后存活为主，击杀额外加分；整场按累计比分排名。
- **整场起伏（独特之处）**：体验版采用悬赏领先者，击败当前累计比分最高的玩家可额外得分。落后者选图或规则、最后几局分值提高作为候选保留，未纳入体验版。
- **里程碑一手感合格标准**：找 3—5 位没玩过的朋友在各自手机上试玩，至少覆盖一台 iPhone 和一台中低端安卓；多数人不看说明几分钟内学会移动、跳跃、射击、捡枪和扔枪，能稳定命中移动木桩，说不出明显“按了没反应”或“误触”的问题，并且愿意再玩一会儿。
- **体验版范围**（用户采纳助手建议）：
  - 包含：好友房 2—6 人；3 张按 6 人尺寸设计的地图；约 4 把射程与射速差异明显的武器，抛物线与反弹类暂不放；一场固定十几局；悬赏领先者、局间计分板与终局排名；木桩练习场（沿用里程碑一）；现成像素素材包，角色只用颜色区分；掉线当局判出局，不做断线重连。
  - 不含：随机匹配、AI、排行榜、角色外观与成长、广告与内购、社交笑点配套（嘲讽、复仇标记、战报分享）、其他起伏机制、公开上架。
- **首个对外版本**：微信体验版，小范围发给朋友，不公开上架。
- **暂定名**：《疯狂枪王》。已有《小小疯狂枪王》《疯狂枪战之王》等相近名称，公开上架前需查重名与商标。

### 助手建议，尚未获用户确认

- 武器刷新点不少于房间人数、靠近各出生点，缩短空手无助的时间。
- 开工前先选定联网方案，代码按“输入→状态”组织，避免单机代码后期难以改为联网。
- 6 人局可读性与旁观：按人数选用不同尺寸地图；用鲜明颜色、轮廓和名字标签区分角色；限制单局时长或加入缩圈、倒计时；旁观时可切换视角或发表情。
- 退路：里程碑二明显超时时，先退到 2—4 人、2 张图、3 把武器，代价是暂时验证不了 6 人局。
- 口号“谁称王，谁挨枪”。
- 社交笑点（嘲讽、复仇标记、战报分享）作为后续配套。
- 隐藏身份的 AI 要有反应延迟、偶尔失误等拟人表现；以后若有排位或奖励，需决定对 AI 的胜负如何计入并核对平台规则。

### 尚未确定

- **引擎与联网方案**：准备阶段第 2 步决定。
- **数值**：一场的具体局数；存活、击杀与悬赏的分值，悬赏是否随分差变化；一次多杀、误伤与自杀是否扣分；同分排名；并列领先时的悬赏；领先者如何标识。
- **武器**：具体名单与参数；刷新点数量与位置、是否局中再刷、各点出什么武器。
- **地图**：3 张地图的设计；是否随人数切换地图尺寸。
- **操作细节**：角度档位、辅助强度；抛物线与反弹类武器的操作。
- **试玩口径**：手感标准里“几分钟”“多数人”的具体口径；体验版各问题的观察口径。
- **后续阶段**：公开上架时间与资质（含是否需要版号）、最终名称、随机匹配与 AI 补位的参数、排行榜、变现方式、抖音等其他平台。

## 主要风险

做不完、触屏手感不成立、微信小游戏实时联网的延迟与稳定性不足、6 人同屏看不清、悬赏没带来悬念、一场十几局对手机太长、公开上架的资质与重名问题、引擎选错导致返工。每项的证据与验证方式见 [交接文档的“风险与待解决问题”](../IdeaLab/ideas/pixel-party-shooter/handoff.md#风险与待解决问题)。
